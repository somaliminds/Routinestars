### A2. Definition of SEN/ALN/ASN and the legal test

| Nation | Term | Legal test | Source |
|---|---|---|---|
| England | Special Educational Need (SEN) | A child/young person has SEN if they have a learning difficulty or disability which calls for special educational provision to be made for them. "Learning difficulty or disability" = significantly greater difficulty in learning than the majority of others of the same age, OR a disability which prevents/hinders use of facilities generally provided. (CAFA 2014 s.20; Code 6.14–6.17) | STATUTORY — CAFA 2014 s.20 |
| Wales | Additional Learning Need (ALN) | A person has ALN if they have a learning difficulty or disability (whatever its origin) which calls for ALP. "Learning difficulty or disability" = significantly greater difficulty in learning than peers, OR a disability preventing/hindering use of educational facilities. ALN replaces the old SEN/LLDD categories and is a single unified concept. (ALN Act 2018 s.2; ALN Code Ch.3) | STATUTORY — ALN Act 2018 s.2 |
| Scotland | Additional Support Need (ASN) | A child/young person has an ASN for whatever reason requires support beyond that normally provided. Reasons include: learning environment; family circumstances; disability/health; social/emotional factors. Broader than SEN — does not require "significantly greater difficulty." (2004 Act s.1; Code 2.1–2.6) | STATUTORY — 2004 Act s.1 |
| Northern Ireland | Special Educational Need (SEN) | A child has SEN if they have a learning difficulty which calls for special educational provision. "Learning difficulty" = significantly greater difficulty in learning than peers, OR a disability hindering use of ordinary educational facilities. (1996 Order Art.31) | STATUTORY — 1996 Order Art.31 |

### A3. Categories / areas of need — controlled vocabulary (enum)

#### England — 4 areas of need (SEND Code 6.27–6.39)
```
AREA_OF_NEED_ENGLAND:
  - COMMUNICATION_AND_INTERACTION
  - COGNITION_AND_LEARNING
  - SOCIAL_EMOTIONAL_AND_MENTAL_HEALTH
  - SENSORY_AND_OR_PHYSICAL
```
Sub-categories (Code 6.28–6.39):
- COMMUNICATION_AND_INTERACTION: speech/language/communication needs (SLCN), autism spectrum (ASD)
- COGNITION_AND_LEARNING: moderate learning difficulty (MLD), severe learning difficulty (SLD), profound & multiple learning difficulty (PMLD), specific learning difficulty (SpLD — dyslexia, dyspraxia, dyscalculia)
- SOCIAL_EMOTIONAL_AND_MENTAL_HEALTH: SEMH (includes ADHD, attachment, anxiety, EBSA)
- SENSORY_AND_OR_PHYSICAL: visual impairment (VI), hearing impairment (HI), multi-sensory impairment (MSI), physical disability (PD)

#### Wales — ALN does NOT use fixed categories
The ALN Act/Code uses a single unified ALN concept. There is **no statutory category enum**. However, the ALN Code (Ch.3) describes the range of needs that may constitute ALN, broadly mirroring England's four areas as descriptive (non-enum) groupings:
```
ALN_DESCRIPTIVE_GROUPING_WALES (non-statutory, descriptive only):
  - COMMUNICATION_AND_INTERACTION
  - COGNITION_AND_LEARNING
  - BEHAVIOURAL_EMOTIONAL_AND_SOCIAL_DEVELOPMENT
  - SENSORY_AND_PHYSICAL
```
> **Implementation note:** Store Wales needs as free-text/descriptive; do NOT enforce England's enum as a statutory taxonomy for Wales.

#### Scotland — ASN does NOT use fixed categories
The 2004 Act defines ASN by reason, not category. The Code (Ch.2) lists factors giving rise to ASN:
```
ASN_REASON_FACTOR_SCOTLAND (descriptive, non-enum):
  - LEARNING_ENVIRONMENT
  - FAMILY_CIRCUMSTANCES
  - DISABILITY_OR_HEALTH
  - SOCIAL_AND_EMOTIONAL_FACTORS
```
Specific needs commonly recorded (non-statutory): learning disability, dyslexia, autism, sensory impairment, physical disability, social/emotional/behavioural, looked-after child status.

#### Northern Ireland — stages of SEN (not categories)
NI uses a **stage** model rather than a category enum:
```
SEN_STAGE_NI:
  - STAGE_1_SCHOOL_BASED  (school action — teacher/SENCO support)
  - STAGE_2_SCHOOL_BASED_PLUS  (external support involved)
  - STAGE_3_STATUTORY_ASSESSMENT  (statement)
  - STAGE_4_STATEMENTED
```
Descriptive need areas mirror England's four areas in practice but are not a statutory enum.

> **Cross-nation enum guidance:** Only England has a statutory 4-area enum. For Wales/Scotland/NI store need descriptions as free-text + optional descriptive grouping tags, never as a hard enum.

## PART B — THE GRADUATED APPROACH / APDR CYCLE

### B1. Structure of the Graduated Approach

#### England — Assess–Plan–Do–Review (SEND Code 6.44–6.67)
| Phase | What must be recorded | Who is responsible | Review cadence | What "good evidence" looks like |
|---|---|---|---|---|
| **Assess** | Baseline data; pupil views; parent views; teacher assessment; specialist advice where sought; identified need + area of need | Class teacher + SENCO (specialist input as needed) | Triggered by concern; reviewed each cycle | Multi-source, dated, triangulated (teacher + parent + pupil + data); identifies barrier & need |
| **Plan** | SMART outcomes; provision (specific, quantified); who delivers; review date; parent/pupil agreement | SENCO + class teacher; agreed with parents & pupil | Each APDR cycle (typically termly) | Outcomes are SMART & specific; provision quantified (frequency, duration, group size); clear success criteria |
| **Do** | Provision delivered as planned; records of delivery; adaptations; observations; progress notes | Class teacher/TA delivering; SENCO oversees | Ongoing during cycle | Dated delivery logs; fidelity to plan recorded; adaptations noted with rationale |
| **Review** | Progress vs outcomes; impact of provision; pupil/parent views; decision: continue/modify/escalate | SENCO + teacher + parents + pupil | End of each cycle (termly minimum) | Quantified progress data; comparative (baseline vs current); clear next-step decision; evidence retained |

#### Wales — ALN provision cycle (ALN Code Ch.4–5)
Wales uses a **plan-do-review** cycle within the IDP rather than a named 4-phase cycle. The IDP itself is the record:
- **Identify ALN** → **IDP created** (outcomes, ALP, review date) → **Deliver ALP** → **Review IDP** (at least annually, or sooner if needs change).
- Statutory status: STATUTORY (ALN Act s.11).

#### Scotland — Staged intervention (Code Ch.4)
Scotland uses a **staged intervention** model (universal → targeted → specialist) within a continuous assess-plan-review loop, not a fixed 4-phase cycle. CSPs apply where multiple agencies need to co-ordinate support.
- Statutory status: STATUTORY GUIDANCE.

#### Northern Ireland — Staged approach (SEN Code NI)
NI uses a 5-stage model (Stages 1–5; Stages 1–2 school-based, Stage 3 EA assessment, Stage 4 statement, Stage 5 review). Stages 1–2 mirror APDR.
- Statutory status: STATUTORY GUIDANCE.

### B2. Longitudinal data that evidences each APDR phase (RoutineStars auto-mapping)

| APDR phase | RoutineStars data fields that evidence it | Why it's credible |
|---|---|---|
| **Assess** | Baseline routine-completion %, timings, streak counts; Zones-of-Regulation distribution over 2+ weeks; environment tags (home/school/respite) showing context variance | Multi-context, dated, longitudinal baseline |
| **Plan** | Target streak/goal set in-app; chosen routine steps flagged as focus; review date set | Quantified, dated target with explicit success criteria |
| **Do** | Daily completion logs (timestamped); step-level timings; adaptations (e.g. visual schedule changes); emotional check-ins during routines | High-frequency, fidelity-to-plan, dated delivery evidence |
| **Review** | Streak trend over cycle; completion % delta vs baseline; emotional-regulation trend; environment comparison; parent/pupil in-app notes | Quantified progress vs baseline; comparative; triangulated with voice |

### C3. EHC Plan — statutory sections (England)

### C6. Pupil/child voice capture — national methods & fields
**Nation(s):** All. **Statutory status:** STATUTORY (England: CAFA s.37(4)(a) — child's views must be sought; Code 9.62. Wales: ALN Code Ch.5 — learner views. Scotland: 2004 Act s.5; GIRFEC. NI: SEN Code Ch.3). **Source:** SEND Code 9.62; ALN Code Ch.5; GIRFEC (gov.scot).

Recognised methods:
- Verbal interview/conversation
- Written/drawn (child's own words/pictures)
- Symbols/Widgit/PECS
- AAC device output
- Video/photo voice
- Observation-based (for non-verbal — record what child does/avoids, facial expressions, regulation states)
- Person-centred planning tools (MAPS, PATH, One Page Profile)

```
CHILD_VOICE_RECORD:
  - child_id
  - date_captured
  - captured_by (role)
  - method (enum: VERBAL | WRITTEN | DRAWN | SYMBOLS | AAC | VIDEO | OBSERVATION | OTHER)

  - child_views (verbatim or described)
  - child_strengths_and_interests[]
  - child_concerns[]
  - child_aspirations[]
  - consent_to_share (parent + child where appropriate)
  - signatures
```

## PART D — OUTCOMES, TARGETS & PROVISION

### D1. Compliant SMART outcome for an EHCP (England)
**Statutory status:** STATUTORY GUIDANCE (Code 9.64–9.69; reg.12). **Source:** SEND Code 9.64–9.69; IPSEA.

A legally adequate outcome must be:
- **Specific** — clear, unambiguous
- **Measurable** — quantifiable progress indicator
- **Achievable** — realistic given needs & provision
- **Relevant** — relates to the child's SEN
- **Time-bound** — clear review/review-by date

An outcome is **inadequate** if it is vague ("will make progress"), unquantified ("will improve communication"), or lacks a timeframe. Outcomes must be distinct from provision.

**Worked examples:**
- ✅ Adequate: "By [date], [child] will independently complete a 5-step morning routine in under 15 minutes on 4 of 5 school days, as recorded by RoutineStars, for two consecutive terms."
- ✅ Adequate: "By the end of Year 5, [child] will use a Zones-of-Regulation strategy to self-regulate from Red/Blue to Green within 5 minutes on 3 of 4 observed occasions."
- ❌ Inadequate: "[Child] will improve their independence." (vague, unmeasurable, no timeframe)
- ❌ Inadequate: "[Child] will receive SALT weekly." (this is provision, not an outcome)

### D2. Outcomes vs provision vs targets
| Concept | Definition | Example | Where it sits |
|---|---|---|---|
| **Outcome** | The intended result/effect for the child; what they will achieve | "Will independently complete morning routine in <15 mins on 4/5 days" | EHCP section E; IDP outcomes |
| **Provision** | The support/intervention delivered to achieve the outcome; what is given | "1:1 visual schedule support daily, 20 mins, by TA" | EHCP section F/G/H; IDP ALP |
| **Target** | A shorter-term stepping-stone milestone toward an outcome (used in SEN Support Plans/IEPs, not statutory in EHCPs) | "Will complete 3 of 5 steps independently by half-term" | SEN Support Plan; IEP |

## PART G — DATA PROTECTION, CONSENT & INFORMATION-SHARING

### G1. UK GDPR + DPA 2018 — sharing child's special-category data
**Statutory status:** STATUTORY. **Source:** UK GDPR (https://gdpr-informationhub.europa.eu); Data Protection Act 2018 (https://www.legislation.gov.uk/ukpga/2018/12/contents); ICO (https://ico.org.uk).

- **Special category data** (UK GDPR Art.9): health data, and data revealing SEN/disability. RoutineStars data (emotional check-ins, routine/behavioural data) likely constitutes health data when it reveals a child's mental health or disability.
- **Lawful bases** (Art.6): for sharing with professionals, the most appropriate is **Art.6(1)(e) public task** (for LA/NHS professionals acting in their official capacity) OR **Art.6(1)(b) contract** (where a direct service contract). **Consent (Art.6(1)(a))** is generally NOT the recommended basis for statutory information-sharing between public bodies, but IS required for sharing with third-party (non-statutory) professionals.
- **Special category condition** (Art.9): for health data sharing, **Art.9(2)(h)** (health/social care provision by or under obligation of a professional) or **Art.9(2)(g)** (substantial public interest) with DPA 2018 Sch.1 conditions.
- **Parental consent** (where consent is the basis): must be **explicit, informed, scoped** (which professionals, which data, which purpose), **time-limited**, and **withdrawable**. Record consent as a structured object:
```
CONSENT_RECORD:
  - child_id
  - consent_given_by (parent | young_person)
  - consent_date
  - consent_scope:
      - professionals_authorised[] (role, name, organisation)
      - data_categories_shared[] (enum)
      - purpose
      - expiry_date
  - withdrawal_date (nullable)
  - withdrawal_logged_by
  - audit_log[] (every access event)
```

### G2. Statutory information-sharing guidance — seven golden rules
**Source:** DfE "Information sharing" guidance (https://www.gov.uk/government/publications/information-sharing-advice-for-safeguarding-practitioners). **Statutory status:** STATUTORY GUIDANCE.

The seven golden rules (DfE information-sharing advice):
1. Remember that the General Data Protection Regulation (GDPR), Data Protection Act 2018 and human rights law are not barriers to justified information sharing but provide a framework to ensure personal information is shared appropriately.
2. Be open and honest with individuals about how and why information is shared.
3. Seek advice from others if you are in any doubt about sharing information.
4. Share with consent where appropriate and, where possible, respect the wishes of those who do not consent.
5. Consider safety and well-being: base information-sharing decisions on the safety and well-being of the individual and others who may be affected.
6. Necessary, proportionate, relevant, adequate, accurate, timely, and secure: ensure information shared is necessary for the purpose, proportionate, relevant, adequate, accurate, and shared securely and in a timely way.
7. Keep a record of your decision and the reasons for it — whether it is to share or not to share.

**What must be logged/audited:**
```
INFORMATION_SHARING_LOG:
  - event_id
  - timestamp
  - shared_by (user, role)
  - shared_with (professional, role, organisation)
  - data_categories_shared[]
  - purpose
  - lawful_basis
  - consent_reference (if applicable)
  - decision_rationale
```

### G3. Under-13s — ICO Children's Code / age-appropriate design
**Source:** ICO Children's Code (https://ico.org.uk/for-organisations/uk-gdpr-guidance-and-resources/childrens-information/childrens-code-guidance-and-resources/). **Statutory status:** STATUTORY (ICO statutory code under DPA 2018 s.123).

The 15 standards of the Children's Code most relevant to a professional-access portal:
1. **Best interests of the child** — primary consideration in design
2. **Data protection impact assessments (DPIAs)** — mandatory for likely high-risk processing of children's data
3. **Age-appropriate application** — apply standards appropriate to age (under-13s require stronger protections)
4. **Transparency** — privacy info in age-appropriate language
5. **Detrimental use of data** — do not use data in ways detrimental to child's wellbeing
6. **Policies and community standards** — uphold published standards
7. **Default settings** — high-privacy defaults for children
8. **Data minimisation** — collect only what's necessary
9. **Data sharing** — do not share children's data unless compelling reason, with appropriate safeguards
10. **Geolocation** — off by default for children
11. **Parental controls** — provide transparent parental controls
12. **Profiling** — off by default for children (unless compelling reason)
13. **Nudge techniques** — do not use nudge techniques to lead children to weaken privacy
14. **Connected toys/devices** — ensure secure
15. **Online tools** — provide prominent, accessible tools for privacy

**Under-13 specific constraints for the portal:**
- Parental consent required for processing (UK GDPR Art.8(1) — child cannot consent alone under 13 in UK for information society services)
- High-privacy defaults; no profiling; data minimisation
- DPIA mandatory before launch

## PART H — EVIDENCE QUALITY STANDARDS

### H1. Strong vs weak evidence in EHC needs assessments & appeals
**Source:** SEND Code 9.14–9.47; First-tier Tribunal (SEND) practice; IPSEA (https://ipsea.org.uk — reference). **Statutory status:** STATUTORY GUIDANCE (Code) / case law (Tribunal).

| Strong evidence | Weak evidence |
|---|---|
| Longitudinal, dated, quantified progress data | Anecdotal, undated assertions |
| Triangulated (teacher + parent + pupil + data) | Single-source opinion |
| Shows what has been tried (APDR cycles) and impact | Lists needs without intervention history |
| From qualified professionals (HCPC-registered) | From unqualified observers |
| Specific, measurable, comparative (baseline vs current) | Vague ("struggling", "not progressing") |
| Consistent across environments (home/school) | Single-context snapshot |
| Includes child's voice | Omits child's views |
| Demonstrates provision delivered with fidelity | Provision claimed without delivery evidence |

**What makes routine/behavioural data credible to LAs/Tribunal:**
- **Frequency:** daily/weekly longitudinal data over weeks/months (not snapshots)
- **Provenance:** timestamped, attributable to a specific child, with delivery context (who, where)
- **Format:** quantified metrics (completion %, timings, streak counts) with baseline for comparison
- **Triangulation:** cross-referenced with teacher/parent/pupil observations
- **Fidelity:** evidence that the planned provision was actually delivered as specified
- **Integrity:** audit trail showing data has not been altered; exportable in a standard format (PDF/CSV with metadata)

### H2. Published guidance on data/technology-collected evidence in SEND
**Statutory status:** GOOD PRACTICE (limited specific statutory guidance). **Sources:**
- SEND Code 9.14–9.47 (evidence for EHC needs assessment — does not specifically address technology-collected data but requires "evidence")
- Education Endowment Foundation (https://educationendowmentfoundation.org.uk) — guidance on using evidence/assessment data (non-authoritative — reference only)
- NICE / SIGN guidelines (for clinical evidence standards)
- No single national statutory guidance specifically addresses app-collected behavioural data in SEND. **Gap — see Gap List.**

## GAP LIST — varies too much by locality to hardcode nationally

1. **Local Authority EHCP request forms & local portals** — each LA has its own forms, portal, and submission process. The national floor is the statutory evidence required (Code 9.14); the form/portal is local. **Do not hardcode forms; build a flexible evidence pack export.**
2. **Ordinarily Available Provision (OAP) / Local Offer** — each LA defines its own OAP and Local Offer. There is no national enum of provision. **Store provision as free-text + quantified fields, not a national enum.**
3. **SEN Support Plan / IDP templates** — no national statutory template; each LA/school produces its own. The national floor is the APDR content requirements (Code 6.44–6.67). **Build a flexible template engine, not a fixed schema.**
4. **"Tell Your Story Once"** — a Milton Keynes LA name (non-authoritative — reference only). The national concept is a parental narrative; structure varies by LA. **Use the generic PARENTAL_NARRATIVE structure (C2), not a local variant.**
5. **Local disagreement resolution / mediation providers** — each LA commissions its own. **Store provider as a configurable field.**
6. **Local EHCP section ordering & formatting** — statutory content (sections A–K) is national, but order/formatting of the PDF varies by LA. **Generate sections A–K as required; allow LA-specific templates.**
7. **NI SEN reform (2025+)** — new regulations and revised Code in development following the 13 Jan 2025 End-to-End Review announcement. **Flag as reform-in-flight; monitor education-ni.gov.uk.**
8. **Scotland Named Person** — commencement of Part 4 (Children & Young People (Scotland) Act 2014) has been selective/contested. **Treat Named Person as policy/good practice unless locally commenced.**
9. **Technology-collected evidence in SEND** — no specific national statutory guidance on app-collected behavioural data. **Align to general evidence-quality standards (H1); flag as a gap.**
10. **Records retention** — IRMS schedule is good practice, not statute; NHS retention differs from schools. **Implement configurable retention rules per record type & body.**
11. **Wales/Scotland/NI need categories** — no statutory enum equivalent to England's 4 areas. **Use free-text + descriptive tags, never a hard enum.**
12. **Local specialist services & pathways** (e.g. MK FACT tool, neurodevelopmental pathways) — local, not national. **Non-authoritative — reference only.**
