# Internationalisation (i18n)

Multilingual support for the **app navigation / UI chrome**, aimed at parents
with limited English.

## Scope (important)

**Translate:** app navigation and UI — buttons, labels, menus, settings,
onboarding, dashboard, the EHCP screens' *navigation* (so a parent can reach and
operate the features).

**Do NOT translate:** the EHCP/SEND **report content** (the generated Annual
Review Pack, One Page Profile, parental narrative in `src/lib/*-report.ts`).
That statutory/medical copy stays English by decision — parents translate those
documents themselves if they wish. Machine translation is unsafe for it.

## How it works

- `src/i18n/index.ts` — i18next init. Language resolution: saved preference
  (`language.store`) → device language (`expo-localization`) → English.
- `src/i18n/locales/*.json` — one nested file per language. English (`en.json`)
  is the source of truth. Missing keys in any language **fall back to English
  per-key**, so a partially-translated language never shows blanks.
- RTL (Urdu `ur`, Arabic `ar`) is applied via `I18nManager`. A full RTL flip
  needs an app restart; the Settings language switcher prompts for it.
- Components use `const { t } = useTranslation()` then `t('settings.language')`.
  Always pass an English fallback during rollout: `t('key', 'English text')`.

Supported: `en, so, pl, ur, cy, ar, pa, bn` (see `SUPPORTED_LANGUAGES`).
Seeded so far: `en` (full source), `pl` + `cy` (demo — first-pass, review before
shipping). The rest are generated by the pipeline below.

## Adding / translating strings

1. **Add English strings** to `src/i18n/locales/en.json` (nested keys) and use
   `t('...')` at the call site. This is the ongoing extraction work.
2. **Machine-translate the new keys** into every language:
   ```bash
   cd apps/mobile
   node scripts/translate-locales.mjs --dry            # count characters, no cost
   GOOGLE_TRANSLATE_API_KEY=xxx npm run i18n:translate  # translate missing keys
   GOOGLE_TRANSLATE_API_KEY=xxx node scripts/translate-locales.mjs --only so,ur
   ```
   The script is **incremental** (only translates keys missing from each target
   file) and **preserves `{{placeholders}}`**. Cost is trivial — the whole app
   chrome is tens of thousands of characters, well inside Google's free tier.
3. **Wire any new language** into `resources` in `src/i18n/index.ts` (add an
   import + entry). `pl`/`cy` show the pattern.
4. **Review the sensitive strings.** Before shipping a language, have a native
   speaker check the **consent** flow and any account/safety copy. The bulk
   (ordinary buttons/labels) is fine machine-translated; the ~consent strings
   are the ones where a wrong word matters.

## Note on quality

The seeded `pl`/`cy` files and any machine output are **first-pass**. They are
safe for ordinary UI but should get a native-speaker pass (especially consent)
before a language is promoted to "supported" in the store listing.
